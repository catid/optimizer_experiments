- PDF: `papers/pdf/2605.10797v1_muown.pdf`
- Source: `papers/src/2605.10797v1_muown/`

- Reference repo from paper source: `https://github.com/kcc-lion/muown`

## Core Idea

Muon controls matrix update direction by orthogonalizing a momentum-like matrix
update. The paper argues that Muon's observed spectral-norm drift is mostly
driven by growth in row magnitudes, while row coherence is comparatively stable.

Muown makes that row magnitude explicit inside the optimizer. For a matrix
`W in R^{m x n}`, it maintains an implicit decomposition:

```text
W(g, R) = Diag(g / ||R||_row) R
```

Here `g in R^m` is the per-row magnitude and `R` is the row-direction variable.
The model still stores only the ordinary `W`; `g`, cached `||R||_row`, and the
magnitude Adam states live in the optimizer.

## Step Math

Let:

```text
r = ||R||_row
D = Diag(1 / r) R
W = Diag(g) D
G = grad_W L(W)
```

The weight-normalized gradients are:

```text
grad_g = (G * D) 1_n
grad_R = Diag(g / r) [G - Diag((G * D) 1_n) D]
```

Then Muown applies:

```text
M_R <- beta M_R + grad_R
U_R <- polar(grad_R + beta M_R)       # simplified Nesterov Muon form
R   <- R - lr * 0.2 * sqrt(max(m,n)) * U_R
g   <- Adam(g, grad_g)
W   <- Diag(g / ||R||_row) R
```

The paper typically runs Muown without ordinary decoupled weight decay. If
decoupled weight decay is applied, the reference code re-syncs `g` to the row
norms of the decayed effective weight because weight decay perturbs `W` away
from the hidden direction variable.

## Reference-Code Audit

The reference implementation is in `optim/muown.py`.

Important matches:

- It initializes `g` and cached `v_norm` from `p.data.norm(dim=1, keepdim=True)`.
- It reconstructs the hidden direction with `u = W / g` and `v = u * v_norm`.
- It computes `grad_g = (grad_W * u).sum(dim=1, keepdim=True)`.
- It computes `grad_v = (g / v_norm) * (grad_W - u * grad_g)`.
- It applies Muon/NS to the direction component and Adam to `g`.
- It recomposes in place as `W[:] = g * v_new / ||v_new||`.
- It special-cases fused QKV matrices with shape `[3d, d]` by orthogonalizing
  q/k/v chunks separately.

Local benchmark implementation:

- Implemented in `workers/codex_noradam_confidence/experiments/run_wikitext_llm50m.py`
  as `Muown`, a subclass of the local `PlainMuon` control.
- Uses the same implicit `W = diag(g / r) R` gradient transformation.
- Uses the same 0.2 `sqrt(max(m,n))` Muon scaling.
- Uses Adam on `g` with betas `(0.9, 0.95)`.
- Keeps QKV handling identical to the existing local `PlainMuon` baseline for
  apples-to-apples comparison in this runner. This differs from the reference
  repo's QKV chunking and should be revisited for a production Muown port.

## Experimental Expectations

The paper reports better robustness to learning-rate and weight-decay choices,
with best Muown runs usually at zero weight decay. For this repo's bounded
50M byte-level FineWeb-Edu proxy, the first fair test should therefore compare:

- tuned Muon with existing weight decay;
- Muown with `weight_decay in {0, 0.01, 0.05}`;
- Muown over a slightly higher LR range than tuned Muon;
- the existing AnchorMuon winner as a strong local baseline.

## Risks

- `g` can become numerically tiny; the local implementation clamps row
  magnitudes to `1e-8`.
- If a row is exactly zero at initialization, the direction is undefined. The
  benchmark model initializes dense nonzero matrices.
- QKV chunking can matter. The local implementation deliberately does not add it
  because the existing Muon control does not have it.
- The byte-level proxy is not a full BPE-tokenized 124M+ FineWeb-Edu reproduction.
