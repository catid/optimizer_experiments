# EMA-Nesterov: Stabilizing Nesterov's Lookahead for Accelerated Deep Learning Optimization

## Core Idea

Classical Nesterov lookahead extrapolates from the last one-step movement:

```text
y_t = x_t + beta (x_t - x_{t-1})
```

The paper argues that this short-horizon signal is noisy in deep learning and
often points into high-loss oscillatory directions. EMA-Nesterov replaces that
one-step direction with a low-pass filtered trajectory direction:

```text
m_{t+1} = gamma m_t + (1 - gamma) (x_{t+1} - x_t)
y_t     = x_t + beta_t m_t
x_{t+1} = A_t(y_t)
```

`A_t` is any base optimizer step, such as Adam, SOAP, Muon, NorMuon, or a more
complex benchmark optimizer.

## Lookahead Schedule

The paper does not keep `beta_t` active for all training. It uses three phases:

```text
early warmup: beta_t = 0
middle:       beta_t = beta * lr_t / lr_max
late rest:    beta_t = 0
```

For the Llama experiments, the source describes a default pattern of roughly
30% warmup and 20% rest. For NanoGPT, the schedule is set by explicit warm/rest
iteration counts.

## Reference-Code Audit

The reference NanoGPT wrapper is `nanogpt/opt_utils.py::EMA_Nesterov`.

Important matches:

- It wraps an inner optimizer rather than replacing that optimizer's update
  rule.
- `nesterov_step()` is called before the model forward pass.
- It adds the EMA lookahead buffer to the current parameters before forward.
- The base optimizer step then updates from the lookahead position.
- `accum_lookahead()` updates the EMA buffer from the new parameter minus the
  previous base parameter.
- With scheduled lookahead enabled, beta is multiplied by the current LR ratio:
  `current_lr / initial_lr`.
- It disables lookahead before the warmup boundary and after the rest boundary.

Local benchmark implementation:

- Implemented in `workers/codex_noradam_confidence/experiments/run_wikitext_llm50m.py`
  as `EMANesterovOptimizer`.
- The local training loop calls `optimizer.zero_grad()` immediately before
  forward; the wrapper uses that call as the pre-forward lookahead hook.
- `step()` delegates to the wrapped optimizer and then updates the EMA direction
  from `x_{t+1} - x_t`.
- The local beta schedule uses the same active-window idea and scales beta by
  the current LR multiplier from the benchmark WSD schedule.
- The benchmark evaluates EMA-Nesterov on top of local `PlainMuon` and local
  `Muown`.

## Experimental Expectations

EMA-Nesterov should be evaluated as a wrapper around a tuned base optimizer. The
paper's useful search range includes:

```text
beta  in {0.1, 0.3, 0.5}
gamma in {0.99, 0.995} for this short-run proxy
```

The most important fairness rule is that base optimizer hyperparameters should
remain recognizable; EMA-Nesterov is a trajectory wrapper, not a new matrix
direction generator.

## Risks

- The lookahead point must be applied before forward/backward. Applying it after
  gradients are computed would test a different algorithm.
- The wrapper must leave parameters at `x_{t+1}` after the optimizer step, not at
  the lookahead point.
- Large `gamma` can retain stale trajectory direction late in training; the rest
  phase is included to avoid this.
- The local wrapper stores full fp32 EMA deltas for all parameters, which is
  fine for this 50M proxy but not free at larger scale.
