## Core Idea

For a layer followed by normalization the gradient is orthogonal to the
weights, `<g_t, x_t> = 0`, so one SGD step with decoupled decay changes the
norm by

```text
||x_{t+1}||^2 = (1 - lambda*gamma)^2 ||x_t||^2 + gamma^2 ||g_t||^2
```

and the steady state is `||g|| / ||x|| = sqrt(2 lambda / gamma)`. With a
schedule the target moves: as `gamma_t -> 0` the ratio wants to grow without
bound, which shows up as the late-training gradient-norm uptick and a falling
weight norm. Decay balances every normalized layer to the same ratio ("layer
balancing"), which is why one global LR works; the schedule breaks that.

## The Fix

Schedule the decay coefficient with the LR:

```text
lambda_t = lambda * gamma_t / gamma_max
x_{t+1}  = x_t - gamma_t * step_t - (gamma_t^2 / gamma_max) * lambda * x_t     # normalized layers
x_{t+1}  = x_t - gamma_t * step_t -  gamma_t                * lambda * x_t     # everything else
```

The steady state becomes `sqrt(2 lambda / gamma_max)`, independent of the
schedule. `gamma_max` only keeps `lambda` on its usual scale: at peak LR the
corrected and standard forms coincide.

Notes that matter for reimplementation:

- **The correction is scoped to normalized layers** (Algorithm 1 has an
  explicit `if layer is normalized` branch). Everything else keeps standard
  AdamW decay. For transformers the paper treats "every linear layer as
  normalized, excluding the output layer of the network".
- The derivation needs `<update, weight> = 0`. For Adam that only holds
  approximately (a weighted-norm argument with a frozen preconditioner); for
  orthogonalized-momentum Muon it does not hold at all without a projection.
- Uncoupled decay (`x - gamma g - lambda_t x`) does not fix it: the steady
  state is then `sqrt(2 lambda_t) / gamma_t`, still schedule dependent.
- The paper's own closing question: "Can any remaining drift in the gradient
  norm be eliminated without using stronger corrections such as projection?"

## Experiments In The Paper

- 120M Llama-3-style LM, FineWeb-Edu, 200B tokens, cosine schedule, batch 256k
  tokens, `wd = 0.05`, LR swept per optimizer. AdamC gives lower loss, removes
  the gradient-norm uptick, and keeps the weight norm flat where AdamW's falls.
  They note 10B tokens is too short to show the effect.
- ImageNet ResNet-50, SGD with momentum, cosine: SGDC removes the end-of-run
  uptick.

## Audit Of The Marin Muon Port

Marin's `MuonCConfig(adamc_weight_decay=True)` multiplies the decay
hyperparameter by `lr_t / peak_lr` for the Muon group and, separately with its
own peak, for the AdamW group. Two things follow:

- It applies the correction to **every decayed parameter**, including
  embeddings and `lm_head` on AdamW. That is wider than the paper's scoping.
- It does **not** project the Muon update, so the orthogonality the derivation
  assumes is not enforced for the matrices either.

hnet's `MuonC` inherits the first point (corrected decay on matrix and fallback
tensors alike) and fixes the second by adding the MuonGS projection.

## Implications For This Repository

- The MuonGS projection makes `<update, W>_F = 0` exact for any direction, so
  under GS the paper's norm recursion holds as an identity instead of an
  approximation, with `||g||` replaced by the (known, nearly constant) norm of
  the Muon direction: `r* = ||O~|| sqrt(eta_max / (2 lambda))`.
- Without the projection Muon's radial drift is first order in `eta_t`. A
  first-order growth term is balanced schedule-independently by *standard*
  decay, not corrected decay. Which decay law is "right" therefore depends on
  whether the tensor is projected; see `workers/claude_muonc_gs/README.md`.
